# Foot Placement / Foot Lock

当前实现针对项目里的 Mixamo 守卫骨架，运行于 Godot 4.7.2；不是 `plan/foot-placement-and-lock.md` 中建议数值和模块结构的逐条移植。保留动画步态、左右脚独立接触阶段和锁定空间的原则，并按现有角色的脚踝高度、速度和节点结构接入。

## 求值与职责

角色每个物理 tick 完成 `move_and_slide()` 后显式推进：

```text
AnimationTree.advance(delta)       # 骨骼动画 + 左右脚连续接触曲线
Skeleton3D.advance(delta)
  MotionPoseSample                # Motion Matching 读取未经过 IK 的双脚姿态／速度
  FootPlacement                   # 原始动画采样、射线、状态机、骨盆补偿
  LeftLegIK : TwoBoneIK3D          # 求解已合成权重的完整目标
  RightLegIK : TwoBoneIK3D
  FootRotations                   # 修正脚掌世界朝向，并记录释放所需的实际腿部输出
```

AnimationTree 和 Skeleton3D 均使用 Manual 回调模式，避免自动回调再推进一次。读取的是当前动画姿态，不是上一帧 IK 的结果。原生修改器按 Skeleton3D 子节点顺序运行；脚掌旋转单独处理，因为当前 TwoBoneIK3D 的 Target 用于位置求解，并不提供鞋底朝向约束。

Motion Matching 的原始姿态采样在本组件之前执行，不读取骨盆／锁脚修正后的姿态；匹配交叉混合时接触曲线也由同一 AnimationTree 混合，匹配不强制清锁。详见 [Motion Matching](../motion_matching/USAGE.md)。

脚部逻辑不移动 CharacterBody3D、碰撞体或相机，也不改变 `get_feet_position()` 及扰雾信号。所有锁点、权重、上一帧姿态和平台引用都保存在各实例的运行时状态中。

## 接触与锁定

`tools/build_mixamo.gd` 从统一到守卫骨架后的动画离线采样鞋底轨迹，生成 `left_contact` / `right_contact` 连续 value tracks。Idle／CrouchIdle 为接触，Jump／Fall 为非接触，行走类根据每只脚的最低鞋底高度及抬起区间估计意图；AnimationTree 原生混合这些属性。它们是基于现有动画的接触估计，不是人工标注的步态事件，更换动画后需要重新检查。

源 Walk 平均根位移速度约为 1.08 m/s，库内步行标准速度为 3 m/s，控制器默认行走 1.5 m/s；当前用户提供的 Run Forward 是原地动画，不能从零根行程直接推断步速。只加 IK 会很快把腿拉到不可达距离，因此重建时先按原根行程校准动画时长，原地 Run 则由支撑区鞋底后移速度估计周期步幅、匹配库内标准 6 m/s；运行默认跑速为 4.5 m/s，由 TimeScale 调整为 0.75 倍速，再删除水平根位移；运行时由 Motion Matching 选择片段和时间，并使用原生 TimeScale 随 Inspector 的行走／跑步／蹲行速度调整节奏；横移及后退同样按原根行程校准。角色位置仍完全由物理控制；没有 Stride Warping 或根运动驱动。

每只脚独立经历：

- **Swing**：动画主导，射线命中本身不触发锁定。
- **Approach**：接触曲线 × 距离权重驱动高度修正，位移和权重采用带速度状态的临界阻尼响应；鞋底水平坐标继续跟随当前动画，不提前锁定。脚掌朝向独立合成，不靠改变水平目标补偿高度。
- **Contact**：接触曲线达到 0.88、脚没有明显上升且已有真实支撑采样后，进入默认 0.12 s 的落地减速。用上一 tick 最终目标在支撑局部坐标中的差分估计入口速度；以短 Hermite 轨迹保留入口位置／速度，终点速度为零。平地水平方向等价于 `P0 + V0 * τ * (u - u²/2)`；终点高度投影到实际支撑平面。脚尚未停稳时不宣布 Stance。
- **Stance**：Contact 结束、支撑相对速度归零时才捕获完整锁点；静态地面上保持世界空间位置，不随角色根移动重新采集。
- **Release**：抬脚、过度转向、超出锁定距离、接触面失效等情况交还动画。停止这条腿的 TwoBoneIK 求解，从上一 tick 实际显示的大腿／小腿局部旋转和角速度开始，将相对当前动画的旋转残差沿五次曲线归零；残差终点的一阶、二阶导数也为零。这样不会因脚踝接近腿长极限而把平滑位置轨迹放大为膝盖突然弯曲。脚掌朝向和骨盆的参考脚踝仍沿世界空间 Hermite 残差交接，但 Release 不再把这个位置强制解成腿部姿态。默认释放时长仍为 `1 / release_speed`，约 0.083 s。输出历史只服务于释放，不反馈到 Motion Matching 的原动画采样。

每只脚采样鞋底中心／脚跟／脚尖三个位置，排除自身 RID、忽略非地面碰撞层和过陡法线；中心无有效支撑时不使用脚尖射线跨越空隙。取足迹范围较高的支撑平面避免鞋底插进下一阶台阶。鞋底偏移在脚踝局部空间标定为 `(0, -0.17, 0.08)` m，默认留 2 cm 鞋底余量；并非把脚踝直接放到碰撞点上。

高度修正、脚掌朝向与水平减速／锁定分别合成为脚踝目标。Approach／Contact／Stance 中目标已含修正权重，原生 IK 以完整 influence 求解，不能再乘一次接触权重，否则会改变落地入口速度；Release 改为腿部局部姿态释放，不再做位置 IK；Swing／禁用／离地仍退出 IK。脚掌保留动画朝前方向的水平投影，限制 pitch／roll 后匹配地面。膝盖 Pole 来自动画弯曲平面并受角色朝前方向约束，不固定在世界方向；目标不可达时先限距，避免拉长骨骼。

## 骨盆与恢复

- 骨盆只沿世界 Y 轴降低：根据髋到目标的水平距离和双段腿长求可达竖向区间，限幅并按 delta 平滑；不是直接取左右脚高度差。默认最多降低 0.25 m，不改上半身动画旋转。
- 所有碰撞支撑均记录弱引用和平台局部锁定变换；平台平移／旋转后转换回世界坐标。demo 验证平移和 yaw，且平台运输速度不计入角色的行走动画速度。
- 跳跃／离地立即去掉腿部 IK，不把脚拖回地面。接触查询丢失、碰撞层过滤、支撑移除或地面改变会释放锁定。
- 根节点单 tick 位移超过 1 m 自动重置；显式传送、复位、复用角色时也可调用 `foot_placement.reset()`。蹲立切换释放旧接触，重新建立落点。

## 配置与诊断

在 `motion_character.tscn` 的 `Visual/Model/Skeleton3D/FootPlacement` 配置组件；`foot_placement/guard.tres` 是可共享的配置资源，独立修改请 Make Unique。运行时通过角色的 `foot_placement` 访问组件。

- `enabled`、`left_enabled`、`right_enabled`：整个系统或单腿开关；请使用这些开关，而不是直接停止第一个修改器的回调，否则后续原生 IK 无法收到清锁更新。
- `settings`：查询范围、地面层、脚底标定、角度／锁距限制及骨盆最大降低量。`approach_speed` 控制临界阻尼响应快慢；`contact_duration` 为落地减速时长（默认 0.12 s，可在 0.04～0.25 s 调整），不是支撑锁定时长；`release_speed` 是释放时长的倒数（默认 12 s⁻¹），不改变抬脚／清锁判据。
- `draw_debug`：世界空间射线、原动画鞋底、接近／锁定目标、法线、髋膝踝链与不可达提示。
- `get_debug_state()`：用于 demo 面板的按脚阶段、接触／距离／修正权重、支撑局部减速速度 `contact_velocity`、锁误差、目标和可达性诊断快照。Release 的 `target` 是骨盆／朝向交接参考，不是强制达到的脚踝位置；实际腿部输出在最后一个修改器完成时读取。

不支持任意重力方向、非单位角色缩放、自动脚步规划、全身平衡、攀爬或台阶自动抬升碰撞体。曲面、边缘及快速动画混合会受三点采样、接触估计与腿部可达范围限制，不保证任意尖锐地形都能无穿插。需要不同骨架时必须重新配置骨名、静止姿态、鞋底坐标和接触曲线。

## Demo 验证路线

打开 `addons/motion/demo.tscn` 按 F6，按 F 控制；Tab 依次跳转检查点，R 重置当前位置：

1. 平地：起步、停步、跑步、蹲行、转向及跳跃；F4 对比原始动画。
2. 蓝色方块：10／18／28 cm 小方块和窄的左右脚高差支撑。
3. 六级楼梯：每级 12 cm、踏面 65 cm；检查点在顶部，W 向下走，可观察跨踏面接触。向上可跳上去；本功能没有实现自动跨台阶的碰撞控制器。
4. 紫色球体：三个不同半径的半埋球，观察左右脚不同法线及边缘释放。
5. 绿色坡面：12° 纵坡、15° 横坡，观察脚掌 pitch／roll 与骨盆降低。
6. 蓝色移动平台：平移和 yaw，观察平台局部锁脚，不应站着原地播放走路。

F3 显示调试线，F4 开关 IK，1／2 独立开关左／右脚；鼠标释放后也可用面板开关和骨盆限幅滑条。蓝色为动画鞋底、黄色为 Approach、橙色为 Contact 减速、绿色为 Stance、品红为 Release、青色为地面法线，红色连线表示不可达目标。低顶通道仍保留，用 Ctrl 蹲行验证。

无窗口接触衔接回归：

```powershell
godot --headless --path . --script res://addons/motion/tests/contact_transition_test.gd
```

该测试通过真实碰撞、原生 AnimationPlayer 接触曲线和最后一个骨骼修改器的输出，检查 60／120 Hz 落地速度变化、刚性支撑坐标系平移／旋转、8 cm 高差、Approach 不抢水平轨迹以及减速中跳跃；另在静态和移动／旋转支撑上，以 60／120／240 Hz 检查 Release 入口和出口的线／角速度差随 tick 缩小而收敛，并独立采样原生动画确认释放后无残留锁定。另通过 `set_external_input()` 驱动完整前走控制器，在同三种频率逐骨骼物理 tick 检查双腿完整 Release 期间的最终大腿／小腿角速度，覆盖接近伸直后突然弯曲的回归；不手动推进动画，也不把一帧渲染内的多次物理更新合并为一个角度差。解锁中跳跃另检查立即恢复原生腿部姿态，落地后仍能重新完成双脚释放。实际 Motion Matching Walk／Run、四象限方向及方向／速度同时混合继续检查双脚静止支撑；斜后方全速跑仍有已知支撑不足，保留其断言。骨骼修改器处理后会恢复动画姿态，不能在任意 process_frame 后读取骨骼来代替最终修改器输出。

Contact 衔接脚部目标的位置／速度，Release 衔接实际腿部局部旋转／角速度并交回动画；没有法线时间滤波、骨盆阻尼重构或 Stride Warping。跳跃／禁用仍立即退出 IK，传送清空历史；不可达限距、支撑突变及动画自身的不连续仍可覆盖正常轨迹，不承诺这些情况下的全身速度连续。

常规回归通过角色的 `set_external_input()` 接收脚本控制，不捕获鼠标、不要求窗口焦点；无窗口运行与可见但不可聚焦的渲染窗口使用同一入口。`tests/foot_placement_test.gd` 从真实 demo 读取 `Skeleton3D.skeleton_updated` 时的最终骨骼姿态，对照实际碰撞和解析台阶／坡面／球面检查落脚、世界空间锁定、摆动释放、步速调整、楼梯下降、移动平台、查询失效、单腿开关、传送和实例隔离；不是只断言目标节点的位置。图形模式运行命令见上级 [USAGE](../USAGE.md)。
